# 垫资对账自动化原型说明

## 本次原型范围

- 新增【余额表】：按 Fund 商户 ID、币种、对账周期查看本期结算金额、累计已确认结算、账户拆分、余额变动时间线和 Fund 回传差异。
- 默认周期来自客户参数，默认 7 天；支持创建周期、单周期日期调整、单笔流水改期，并记录原因、操作者、版本和原周期。
- 【垫资 PayPal 明细】的业务入口并入【平台收款明细】。统一展示 PayPal、Airwallex、Oceanpayment、ShopifyPayments 的 Fund 同步流水，并提供渠道筛选、同步结果、重复和待处理数据提示。
- 【订单匹配】使用 payment reference 与账单号，允许一单多流水。未匹配、多重匹配和缺少账户映射的记录不进入结算。
- 【对账管理】提供财务复核、费用/金额调整、客户确认、对账单导出、Fund 同步和已确认周期更正申请入口。
- 【Fund 联动】提供账户期初维护、跨账户调拨、单账户手动调整、审批和执行状态、Fund 余额回传、账户账本查看。

## 数据归属和状态

对账系统负责店铺订单、Fund 渠道流水、订单匹配、周期结算和客户余额表。Fund 负责渠道账户余额、冻结金额、期初余额、调拨/手调执行和资金账本。渠道实际余额与内部结算余额池独立保存。

周期状态：`对账中 → 待客户确认 → 已确认 → 已同步 Fund`。同步失败保留为 `同步失败`，可以按原周期版本幂等重试。只有 Fund 执行成功才改变内部余额池；审批通过、发起请求和执行中不算入账。

## 已在原型中演示的联动

1. 客户管理修改默认周期、服务费和保证金；新周期保存当时的参数快照。
2. 平台收款明细从 Fund 流水同步，使用来源 + 平台 + 资金账户 + Event ID 去重。已锁定周期和账户映射缺失的流水进入待处理，不自动落账。
3. 对账表按账户拆分计算收款、退款、拒付/追回、渠道费用、客户服务费、保证金和人工调整，再汇总到客户/币种。
4. 财务复核后登记客户确认凭据，确认后锁定周期。已锁定周期不能直接覆盖，进入更正申请。
5. Fund 期初、调拨和手调沿用“飞书审批 → Fund 执行 → 余额回传”状态链。调拨的转出和转入分别记账，不能用一次客户汇总直接抵销账户明细。

## 需要评审确认的口径

- 每期结果按“本期增量”累计，还是 Excel `Total` 代表期末存量。
- 客户余额池按商户 ID + 币种维护，还是必须分到具体渠道资金账户。
- 服务费和保证金的基数、跨币种折算、退款/拒付是否影响基数、准备金释放规则。
- 周期归属使用 Shopify 订单时间、渠道交易时间、渠道入账时间还是 Fund 入账时间。
- 已确认对账单的更正、冲正、重新入账和审批路径。
- Fund 余额回传的接口契约、事件版本、幂等键、失败重试、补偿和回传时间。
- 期初余额的生效日、是否允许历史补录、修改审批和多账户初始化规则。

原型页面使用模拟数据，仅用于确认页面结构和交互流程，不连接真实 Fund、Shopify 或飞书，也不会执行真实资金变动。
